## [OpenAI's Navier-Stokes Release Includes a Lean 4 Formal Proof](https://www.johndcook.com/blog/2026/09/09/formal-method-revolution/) ⭐️ 9.0/10

On 8 September 2026, OpenAI claimed a proof that Navier-Stokes solutions break down in three-dimensional Euclidean space, and the release included a formalization in the Lean 4 proof assistant produced by a swarm of roughly 10,000 AI agents running an internal frontier model. The counter-example, which resembles a spinning top tightening to a singularity with diverging velocities, has not yet been verified by external mathematicians or the Clay Mathematics Institute. If it holds up, this would be the first time an AI system has produced a formal proof of a Millennium Prize-level problem, marking a major milestone for AI-driven mathematics and automated theorem proving. It also intensifies the debate over how AI research is credited, given the accompanying priority dispute with researchers at rival AI company Anthropic. The proof was generated by a large fleet of agents at an estimated cost of around $40 million, and OpenAI stated it would not claim the $1 million Clay Millennium Prize for the solution. The method builds on a 2023 technique by Diego Córdoba and Luis Martínez-Zoroa for finding blowup phenomena in related fluid equations, and the result is closely related to earlier Euler-equation work by Levent Alpöge and Tristan Buckmaster.

hackernews · ibobev · Sep 10, 21:22 · [Discussion](https://news.ycombinator.com/item?id=49650326)

**Background**: Lean is a proof assistant and functional programming language based on the Calculus of Inductive Constructions, and Lean 4 is a reimplementation of Lean in Lean itself that compiles to C, allowing users to write efficient proof automation. The Navier-Stokes existence and smoothness problem asks whether the equations describing fluid motion always have smooth, globally defined solutions in three dimensions, and the Clay Mathematics Institute named it one of seven Millennium Prize Problems in 2000. Formal verification means using formal methods of mathematics to prove or disprove the correctness of a system against a precise specification, which is what a Lean proof provides for a mathematical statement.

## [Show-Harness Lets VLMs Control Robots via Semantic Actions](https://huggingface.co/papers/2609.10522) ⭐️ 8.0/10

Show-Harness introduces an Embodied Harness that exposes discrete semantic action units which vision-language models can reason over, while embodiment-specific interpreters deterministically ground those units into local robot actions. The paper demonstrates zero-shot control using closed-source frontier VLMs and low-cost adaptation of small open-source VLMs with only a few GPU-hours of fine-tuning, plus GUMI for GUI-based demonstration collection. This work suggests that a well-designed semantic interface can unlock substantial embodied capability from foundation VLMs without extra model capacity or costly embodiment-specific pretraining, potentially lowering the barrier to deploying general-purpose robot control. It could affect robotics and embodied AI research by offering an alternative to end-to-end vision-language-action (VLA) paradigms. The interface keeps the VLM directly responsible for fine-grained physical decisions, while deterministic interpreters handle grounding into robot-specific commands; the same semantic action space is extended to GUI-based demonstration collection via GUMI, removing the need for specialized teleoperation hardware. Experiments report that Show-Harness-equipped VLM agents generalize robustly across tasks, embodiments, and environments, outperforming representative agentic and VLA paradigms.

huggingface_papers · Hugging Face Papers · Sep 10, 00:00

**Background**: Vision-language models (VLMs) are foundation models pretrained on large amounts of image-text data, giving them broad world knowledge and reasoning ability, but translating that knowledge into physical robot control is difficult because robot hardware and low-level commands differ across embodiments. Vision-language-action (VLA) models typically fine-tune such models end-to-end on robot data, which is expensive and embodiment-specific. Show-Harness instead inserts a compact semantic action interface between the VLM and the robot, so the VLM outputs discrete semantic actions that embodiment-specific interpreters convert into local commands.

## [Programmable World Model Decouples State from Video Generation](https://huggingface.co/papers/2609.10540) ⭐️ 8.0/10

Researchers introduce Programmable World Model, a framework that separates explicit world-state evolution from visual observation generation by translating natural-language instructions into executable programs that define entity states and state-transition rules. Using state-augmented 3D oriented bounding boxes (OBBs) as an intermediate representation, the system compiles world state and camera trajectory into conditioning signals for a pretrained video model, achieving 94% Count Accuracy and 98% State Accuracy on the new CombatStateBench benchmark. This work addresses a core limitation of current video world models—their inability to maintain persistent state and enforce programmable rules over long interactions—which is essential for building playable games, interactive simulations, and controllable AI environments. By decoupling state evolution from rendering, it points toward a modular architecture where explicit symbolic reasoning and generative rendering can be developed and improved independently. The framework maintains an explicit global world state that includes off-screen entities and non-visual attributes, and it deterministically compiles state-augmented 3D OBBs plus the target camera trajectory into pixel-aligned spatiotemporal conditioning signals. The authors also release CombatStateBench, a benchmark for evaluating programmable world models, on which their method substantially outperforms existing interactive video world models while supporting coherent long-horizon generation.

huggingface_papers · Hugging Face Papers · Sep 10, 00:00

**Background**: World models in AI are systems that build an internal representation of an environment and predict how it changes over time in response to actions, helping agents plan and reason without constant real-world trial and error. Recent video world models generate increasingly realistic interactive visuals but typically lack a reliable mechanism for persistent state or programmable rules. Oriented bounding boxes (OBBs) are 3D boxes that enclose objects with arbitrary orientation, commonly used in 3D detection and spatial reasoning, while rule-based systems represent domain knowledge as explicit if-then rules. This paper combines these ideas by using executable programs for state transitions and OBBs as the bridge between symbolic state and a pretrained video renderer.

## [Forgejo 16.0.4 Fixes Critical RCE in Template Repositories](https://codeberg.org/forgejo/forgejo/src/branch/forgejo/release-notes-published/16.0.4.md) ⭐️ 8.0/10

Forgejo versions up to and including 16.0.3 contain a critical remote code execution vulnerability (CVE-2026-89094) related to template repository initialization, which has been fixed in the 16.0.4 and 15.0.8 releases. The flaw allows an attacker to achieve remote code execution via a crafted template repository because template expansion on files in the .forgejo/template directory is mishandled. Forgejo is a widely used self-hosted Git service, so a critical RCE rated CVSS 9.9 puts many organizations' code and infrastructure at risk if they do not upgrade promptly. The vulnerability also highlights the security challenges facing community-maintained forks of popular platforms like Gitea. The vulnerability is tracked as CVE-2026-89094 with a CVSS score of 9.9, and it is triggered when generating a new repository from a template repository, during which Forgejo clones the template, removes the .git folder, performs variable template expansion on files listed in .forgejo/template, and initializes a new git repository. The fix is included in Forgejo 16.0.4 and the backported 15.0.8 release.

hackernews · weierstass · Sep 10, 15:57 · [Discussion](https://news.ycombinator.com/item?id=49645907)

**Background**: Forgejo is a community-driven, self-hosted Git forge that was forked from Gitea in 2022, offering repository hosting, issue tracking, and CI features similar to GitHub or GitLab. Template repositories let users scaffold new projects from a predefined structure, and the template expansion step substitutes variables into files during that process. A mishandling of this expansion step can let crafted content execute code on the server, which is why the issue is classified as a critical remote code execution flaw.

## [JEP 544 Proposes Ahead-of-Time Code Compilation for Java](https://openjdk.org/jeps/544) ⭐️ 8.0/10

OpenJDK has published JEP 544, a proposal by Oracle's John Rose that extends Project Leyden's AOT cache mechanism to store optimized native code produced during training runs, aiming to eliminate Java's slow startup and warm-up phases. If accepted, this could significantly reduce Java application startup time and time-to-peak-performance, benefiting cloud-native and serverless workloads where cold starts are costly, and it continues OpenJDK's multi-JEP push toward native-like performance. The proposal builds on the AOT cache introduced in earlier Leyden JEPs (such as JEP 483 in Java 25) and assumes a training run is a good source of observations for production; future work includes investigating near-total reliance on AOT code, though initial experiments suggest minimizing interpreter use leads to overly large cache files that can take longer to load than simply interpreting.

hackernews · Skinney · Sep 10, 17:30 · [Discussion](https://news.ycombinator.com/item?id=49647404)

**Background**: Ahead-of-time (AOT) compilation converts higher-level code into native machine code before execution, typically at build time, to reduce runtime work. Java has traditionally relied on just-in-time (JIT) compilation, where the JVM interprets bytecode and compiles frequently executed code to native code at runtime, causing slow startup and warm-up. Project Leyden is an OpenJDK research effort shipping one JEP at a time to bring AOT benefits to Java without sacrificing its dynamic optimizations.
