## [SFT Conflicts, RL Coexists: Multi-Task Learning Analysis for LLMs](https://huggingface.co/papers/2608.03573) ⭐️ 8.0/10

This paper provides a theoretical and empirical analysis showing that SFT suffers from norm-limited gradient interference causing task conflicts, while RL exhibits variance-limited interference leading to near-orthogonal updates and stable multi-task coexistence. Based on this insight, the authors propose Parallel-RL, a paradigm that decouples multi-task training to improve efficiency and flexibility. This research clarifies the fundamental differences between SFT and RL in multi-task learning, offering a theoretical basis for choosing training paradigms. The proposed Parallel-RL could lead to more efficient and scalable LLM training strategies, impacting the broader AI community. The distinction is that SFT interference scales with absolute gradient magnitude (norm-limited), while RL interference is bounded by gradient variance from advantage normalization and on-policy optimization (variance-limited). This small variance bound results in near-orthogonal optimization directions across tasks, enabling stable coexistence.

huggingface_papers · Hugging Face Papers · Aug 10, 00:00

**Background**: Supervised Fine-Tuning (SFT) and Reinforcement Learning (RL) are two common paradigms for adapting large language models (LLMs) to specific tasks. In multi-task settings, SFT often suffers from task conflicts, whereas RL can handle multiple tasks simultaneously. This paper provides a theoretical explanation for this observed difference, focusing on gradient interference.

## [Exploiting System Management Mode with a Very Long Interrupt](https://github.com/xoreaxeaxeax/smiiiiiiiiiiiiiiii) ⭐️ 8.0/10

A security researcher has demonstrated a novel technique to exploit System Management Mode (SMM) by using an extremely long interrupt, potentially allowing an attacker with root privileges to execute arbitrary code within SMM. The proof-of-concept is available on GitHub. This research highlights a hardware-level security concern that could undermine the security guarantees of UEFI firmware and the entire operating system. It underscores the ongoing tension between user control and vendor-imposed restrictions in modern CPUs. The technique relies on the fact that SMM handlers are invoked between instructions, and a sufficiently long instruction can delay the interrupt, potentially causing race conditions or other unexpected behavior. The researcher notes that firmware designers anticipate this attack but often defer to the platform implementor to choose an appropriate timeout value.

hackernews · WhiteDawn · Aug 10, 16:03 · [Discussion](https://news.ycombinator.com/item?id=49245491)

**Background**: System Management Mode (SMM) is a special CPU mode used for low-level platform management, such as power management and hardware control. It is triggered by a System Management Interrupt (SMI), which saves the processor state, runs a firmware-provided handler, and then restores the state. SMM operates in a separate memory region that is typically inaccessible to the operating system, making it an attractive target for attackers seeking to bypass security mechanisms.

## [Docker Sandboxes: MicroVM-Based Isolation for AI Agents](https://www.docker.com/products/docker-sandboxes/) ⭐️ 8.0/10

Docker has launched Docker Sandboxes, a new product that provides disposable, isolated microVM-based sandboxes for AI coding agents like Claude Code, Gemini, Codex, and Kiro. Each sandbox runs as a microVM with its own kernel, using a custom VMM built on native hypervisors (Hypervisor.framework, WHP, KVM). This is significant because it addresses a critical security concern in the AI agent ecosystem: standard containers share the host kernel, making them insufficient for isolating potentially untrusted AI-generated code. By offering microVM-based isolation, Docker provides a stronger security boundary, which could become a standard for running AI agents safely in development environments. Each sandbox gets its own private Docker daemon, hypervisor-level isolation, and network filtering. Docker wrote a new VMM (not Firecracker) to work effectively across platforms, and the product is currently available on Docker's platform, with a CLI tool called 'sbx' for managing sandboxes.

hackernews · etoxin · Aug 10, 06:02 · [Discussion](https://news.ycombinator.com/item?id=49239751)

**Background**: AI agents often execute code or commands on behalf of users, which can be risky if the code is malicious or buggy. Traditional container sandboxes share the host kernel, so a container escape could compromise the entire host. MicroVMs provide a stronger isolation boundary by running each sandbox with its own kernel, making them more secure for untrusted code execution.
